## 3. Defects & Coverage Gaps Found and Remediated in WP4

1. **`WP4-DEF-01` (P1 — Runtime Defect): Valid offline shared-device v2 PIN unlock stayed trapped in Child Mode (`C0-09` / `C0-I05`)**
   - **Location:** `apps/mobile/lib/app/bootstrap/cold_start_containment_bootstrap.dart` (`SessionLifecycleController.submitParentGateUnlock`, Step 4 & post-commit publication).
   - **Reproducer:** Boot offline into `ChildModeOfflineContained` with valid v2 PIN + matching same-actor `shared_device_adult` session and zero recovery lock, then solve PIN `8392`. Prior code rejected offline `SessionAuthorizationUnverified` identically to `ConfirmedAdultMembershipRevoked`, leaving the parent stuck unable to reach `/account/unverified`.
   - **Fix:** When `outcome is SessionAuthorizationUnverified` AND `validV2` credential + matching same-actor `shared_device_adult` session + zero `containment_recovery_lock_v1` + household ownership match hold, Step 5 atomically clears `active_child_session`, resets lockout, advances `containment_fence_v1`, and transitions UI strictly to `authorizationUnverified` (`/account/unverified`, `activeFamilyProvider == null`, never `verifiedParentMode`). `ConfirmedAdultMembershipRevoked`, legacy v1 offline, paired-child, and locked states continue failing closed (`pinMatchedAuthorizationRequired`).
   - **Regression Tests:** `C0-09` in `wp4_slice_4c0_acceptance_matrix_test.dart`; updated `wp3_session_lifecycle_and_router_test.dart` (`L1664`, `L2684`).

2. **`WP4-DEF-02` (P1 — Concurrency / Fencing Defect): `submitParentPinChange` and `submitCrossFamilyPinReassignment` lacked family-switch fence checks, Barrier 1/2 hooks, `containment_fence_v1` mutation & `abortFencedAttempt` (`C0-32`, `C0-37`)**
   - **Location:** `apps/mobile/lib/app/bootstrap/cold_start_containment_bootstrap.dart` (`submitParentPinChange`, `submitCrossFamilyPinReassignment`).
   - **Reproducer:** Start `submitParentPinChange` in Family 1, pause mid-KDF (or Barrier 1/2), switch to Family 2. Because `switchActiveFamily` preserves `actorUserId`, `sessionGeneration`, and previously did not invalidate `verifiedFamilyId` inside `submitParentPinChange`/`submitCrossFamilyPinReassignment`, the stale Family 1 change could overwrite Family 2's family scope or leave stale reservations.
   - **Fix:** Added `state.status == ColdStartContainmentStatus.verifiedParentMode && state.verifiedFamily?.id.value == prepared.targetFamilyId` checks at admission, post-KDF, inside `_arbiter`, inside `preCommitGuard`, and post-commit Barrier 2; exposed Barrier 1/2 hooks; added `containment_fence_v1` CAS upsert to `submitParentPinChange`; called `abortFencedAttempt(staged.attemptId)` on stale cancellation.
   - **Regression Tests:** `C0-32` & all 8 `submitParentPinChange` `C0-37` tests in `wp4_slice_4c0_acceptance_matrix_test.dart`.

3. **`WP4-DEF-03` (P1 — Containment Downgrade Precedence): Blocking `_pauseMismatchedActorRewardCommands` and missing synchronous containment downgrade hook (`C0-33`, `C0-37(d)`)**
   - **Location:** `apps/mobile/lib/app/bootstrap/cold_start_containment_bootstrap.dart` (`applyContainmentInvalidation`, `_performRehydratePass`).
   - **Fix:** Added synchronous (`0 await`) `applyContainmentInvalidation(...)` bumping `_containmentEpoch++`, clearing protected state immediately, and queuing `_persistFenceTransition()`. Reordered `_performRehydratePass` so `verifier.verifySession(...)` executes and bumps `_containmentEpoch++` on downgrades before awaiting `_arbiter` for `_pauseMismatchedActorRewardCommands`.
   - **Regression Tests:** `C0-33` and `[containment_downgrade]` Barrier 1/2 tests in `wp4_slice_4c0_acceptance_matrix_test.dart`.

4. **`WP4-GAP-01` (Coverage Gap): RFC 7914 §11 64-byte PBKDF2-HMAC-SHA-256 test vectors & explicit <100k failure assertion (`C0-15`)**
   - **Location:** `apps/mobile/test/wp1_parent_gate_v2_test.dart`.
   - **Fix:** Added exact RFC 7914 §11 vectors (`passwd`/`salt`/c=1/dkLen=64, `Password`/`NaCl`/c=80000/dkLen=64, `pleaseletmein`/`SodiumChloride`/c=16384/dkLen=64) and verified `99999`-iteration payload fails closed as `ParentGateCredentialStatus.corrupt`.

5. **`WP4-DEF-04` (P1 — Barrier 2 Post-Commit Epoch Masking): `_containmentEpoch++` masked in-Barrier-2 invalidations in `submitParentGateUnlock`, `submitInitialPinSetup`, `submitParentPinChange`, and `submitCrossFamilyPinReassignment` (`C0-37`)**
   - **Location:** `apps/mobile/lib/app/bootstrap/cold_start_containment_bootstrap.dart`.
   - **Reproducer:** When `[unlock][barrier2][containment_downgrade]` fired `applyContainmentInvalidation` during `onAfterFinalizeGuardBeforeCommit`, `_containmentEpoch` bumped inside Barrier 2; `submitParentGateUnlock` then unconditionally ran `_containmentEpoch++; postCommitEpoch = _containmentEpoch;` before checking `_isFenceStillValid`, causing it to return `PinVerificationOutcome.verified` instead of `staleFence`.
   - **Fix:** Check pre-commit fence validity (`capturedEpoch`, `capturedGeneration`, `capturedActorId`, and active `verifiedParentMode`/`verifiedFamilyId` for Parent operations) BEFORE bumping `_containmentEpoch++`, record `invalidatedDuringCommit`, and return `staleFence` / throw `ParentGateFencedOperationException` while preserving an already-applied `containmentLocked` / `unauthenticated` state without overwriting to `hydrating`.
   - **Regression Tests:** All 16 Barrier 1/Barrier 2 permutations in `Group C` of `wp4_slice_4c0_acceptance_matrix_test.dart`.

6. **`WP4-DEF-05` (Defense-in-Depth — Anonymous/Child Actor Guard in `resolveColdStartContainmentState` (`C0-29`))**
   - **Location:** `apps/mobile/lib/app/bootstrap/cold_start_containment_bootstrap.dart` (`resolveColdStartContainmentState`).
   - **Fix:** Guarded `AuthorizedActiveAdult` and `NoActiveFamilyMembershipObserved` cases so `actorContext.isAnonymous || actorContext.role == 'child'` always resolves fail-closed to `ColdStartContainmentStatus.pairedChildUnverified` even if a stale/mocked verifier emitted an adult/onboarding outcome.
   - **Regression Tests:** `C0-19, C0-28, C0-29, C0-36` in `wp4_slice_4c0_acceptance_matrix_test.dart`.

7. **`WP4-DEF-06` (P1 — Stale Pre-Arbiter `containment_fence_v1` Snapshot Stalling Exit Path B Auto-Unlock (`C0-30`))**
   - **Location:** `apps/mobile/lib/app/bootstrap/cold_start_containment_bootstrap.dart` (`_performRehydratePass` Exit Path B auto-unlock transaction).
   - **Reproducer:** When an auth transition queued `_persistFenceTransition()` on `_arbiter` immediately prior to `rehydrate()`, `_performRehydratePass` read `rawFence` before waiting for `_arbiter`, so `_persistFenceTransition()` updated `containment_fence_v1` in SQLite before the Exit Path B `compareAndSwapMetadataBatch`, causing CAS to fail and leaving a fresh owning adult stuck in `containmentLocked`.
   - **Fix:** Re-read `liveRawFence` inside `_arbiter.run(...)` ahead of the atomic Exit Path B CAS (while retaining `_containmentEpoch == capturedEpoch` and session-generation checks in `preCommitGuard` so any subsequent invalidation still aborts).
   - **Regression Tests:** `C0-30 & C0-38` in `wp4_slice_4c0_acceptance_matrix_test.dart`.
